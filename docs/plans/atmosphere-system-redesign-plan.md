## 〇、玩家体验目标（评审 P1-1 增补，各 Phase 过审标准）

1. **长期目标感**：每次上线都知道「我在为下一个升阶仪式攒钱攒任务」，而不是看着水位条无意义地涨
2. **资源博弈**：花氛围升设施（产能）还是攒着升阶（地位）还是兑灵感（即时爽），三选一要有真实的取舍痛感
3. **固定资产养成**：设施是「我的图书馆在实体上变好了」的可见证据，升级瞬间要有仪式感

## 二、系统模型（P0-1 修订：stage 独立字段，peak 只作仪式门槛）

**状态 schema 新增（migration 一并落地）**：
```
state.library.atmospherePeak   // 历史最高水位（只增不减；v3.4 后不再作阶段门槛，留作统计/展示）
state.library.stage            // 当前阶段 1-5，独立字段，仪式推进
state.library.totalEarned      // 累计获得氛围（=阶段仪式门槛，v3.4 仿真修正⚠待确认）
state.library.freeAtmosphere   // 自由氛围池（软顶 3000 主闸，见 §五；兼作大额支付储蓄账户）
state.library.materials        // 修缮材料（设施每日产出，Phase 3 任务链物资）
state.books[bookId].borrowCount // 借阅磨损计数（决策 9）
```

**阶段推进（修订后唯一路径，v3.4 门槛改累计制⚠待确认）**：
```
totalEarned ≥ 门槛[N+1]  →  解锁「N→N+1 升阶仪式」入口
     ↓（手动发起）
余额支付大笔氛围（不足自动动用自由池） + 完成本阶修缮任务链
     ↓
state.library.stage++（永久，之后花光库存也不掉段）
```
- **5 阶段**（评审 P0-3 勘误，原写 6 有误）：废墟 0-30 / 破败 30-80 / 陈旧 80-160 / 温暖 160-300 / 星辰 300-500，沿用 `data/atmosphere.js` 现有叙事
- 阈值语义改变：不再「自动跳阶」，只决定「仪式可发起」
- **两套 stage 推导函数同时停薪**：`getAtmosphereStage`(data/atmosphere.js) 与 `getAtmosphereLevel`(economy.js) 改为只读 `state.library.stage`（评审 P2-5）；全部 ~25 文件 / ~75 处 `state.library.atmosphere` 读取需全局排查分流（评审 P2-4）

```
            抄写 / 还书 / 访客事件 / 植物 / 一次性加成
                    ↓ 流入                      ┌─ 设施每日产出 → 修缮材料（不进气氛围经济）
            ┌──────────────┐   溢出(满500)     │
            │  藏书厅库存   │ ─────────────→ ┌──────────────┐
            │  cap 500     │                │ 自由氛围池     │
            └──────┬───────┘                │ 软顶 3000 主闸 │
                   │ 消耗                    └───┬───────┬──┘
                   ↓                             │       │
        设施升级(双消耗) / 升阶仪式          兑灵感     场馆房间
        （新升级收氛围，老档不追溯）        (日上限)   (维持费<房间收益)
        
⚠ 火灾罚金可透支：先扣库存，不足扣自由池（D9，防「零库存免疫火灾」）
```

**产能观修订（二轮评审 P0-12 洞察）**：设施 = 产能的真正杠杆是**借阅区还书流**（cap 2→10 × returnAtmo 1→5，理论产能差 25 倍），不是每日产出。日产改修缮材料后，氛围产能回到单一主导来源（还书），经济模型更干净。

## 三、数值框架（**v3.4 仿真标定**，周转率 1.5 基准；脚本 `scripts/simulate-atmosphere-economy.mjs`）

v3.4 发现 500 顶 < 大额支出卡死 + 年需求 ≈ 年流水 85% 超支 → 成本减半定版。

## 四、借还子系统改造（决策 9 + 典藏回报）

- `borrowCount` 持久化（migration 默认 0；存量老书默认 0 = 隐性元老福利）
- `getDamageChance(borrowLevel, hasCareSignboard, wearCount)`：磨损**乘性**注入（§三表）；**三个调用点必须传该书 wearCount**——还书结算 `visitors.js:1183`、书卡展示 `render/visitors.js:104`、升级弹窗 `render/shop/library-upgrades.js:68`（评审 P2-1，漏传则磨损不生效）
- 附带修复（评审 P1-7）：「爱惜书籍」标志牌在高借阅区等级几乎无效（0.6%→0.5%）是既有问题，磨损乘性化后一并重调 care 牌效果
- 书卡/详情显示**书况**（磨损星级），重抄按钮旁提示「重抄可恢复书况」
- **磨损清零钩子：挂在 `book-progress.js:63`（copyCount 落点，即重抄真正完成处）**
- **磨损→重抄→灵感 sink 链条（评审 P1-8 点明，纳入 Phase 0 测算）**：重抄花费 1 灵感（`book-progress.js:171`），是全局唯一成规模的灵感 sink——磨损速率直接决定灵感回收强度，与 DLC 灵感售卖汇率联动校核
- 典藏版还书：`returnCoins ×2 + returnAtmo ×3`，配专属访客台词（与 visitor-book-review-notes 联动点）

## 五、通胀闸（v3 重写：软顶主闸 + 日上限，评审 D11/D12）

自由池无上限 + 溢出常开 = 堆积隐患；直通 50:1 灵感则衔接 DLC 购买力。定闸：

1. **主闸 = 自由池软顶 3000（D12）**：超出停增或 10:1 折损 [PLACEHOLDER]，与藏书厅 500 顶同构，最简单可控
2. **兑灵感每日上限 200 池（=4 灵感）**：防灵感侧通胀，UI 明示「明日再来」
3. ~~维持费恒大于日产~~（v2 闸 2 作废，评审 P1-5）：场馆维持费改为**小于房间收益**——房间是值得建的玩法内容（茶室羁绊/温室植物/庭院活动/档案室馆史），作用是「放缓自由池积累」而非「转负」；否则房间变负资产无人建造，Phase 5 自毁

`50:1`、软顶值与磨损速率由 P0 测算定（见 §七 Phase 0，含磨损↔重抄↔灵感链条校核）。
