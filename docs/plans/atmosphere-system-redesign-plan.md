# 氛围系统重设计（atmosphere-system-redesign）

> 立项：2026-09-08，图南发起并 grill 锁定 10 项决策。**本文档吸收合并 atmosphere-venue-map-design（场馆修复地图）**，
> 后者不再单独实施；economy-balance-review 中「溢出折算/典藏收益」两条随之落地。
>
> 核心命题：氛围从「水位值」重设计为**消耗品**——有库存、有产能、有消费口，设施成为固定资产。

---

## 一、十个已锁定决策（2026-09-08 grill 全记录）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 阶段与库存关系 | **最高水位制**：阶段只进不退，库存可花。state 新增 `atmospherePeak` |
| 2 | 库存上限 | **双池制**：藏书厅库存保 500 封顶，溢出自动入**自由氛围池**（无上限） |
| 3 | 升阶机制 | **升阶仪式制**：攒够后手动发起仪式，消耗大笔氛围 + 完成修缮任务链，成功后阶段永久 +1（不再自动跳） |
| 4 | 设施固定氛围形态 | **一次性 + 每日混合**：升级时一次性大头入库存，之后每日结算小产出（离线补算） |
| 5 | 设施范围 | 设计全覆盖；**MVP 三项**：缮写室 / 借阅区 / 修复室 |
| 6 | 双消耗曲线 | **占比随级爬升**：低等级纯智慧之光（新手保护），高等级氛围成大头 |
| 7 | 升阶前置 | **修缮任务链**：每阶一串修缮任务（物资+氛围），设施等级是链上一环 |
| 8 | 老档迁移 | **保底映射 + 不追溯**：阶段 1:1 初始化、设施一次性加成补发入库存、每日产出自今日起算、赠「开馆元老」成就+称号 |
| 9 | 损毁递增 | **单书借阅磨损**：每本书的还书损毁率随借出次数缓升；**重抄清零** |
| 10 | 自由池出口 | **50:1 兑灵感 + 四个场馆房间**（茶室/温室/庭院/档案室，吸收 venue 方案） |

补充决策（图南插单）：**典藏版借出回报调高**——典藏版免疫损毁+免疫磨损，作为对价还书收益（智慧之光/氛围）显著上调，坐实「终极产物」地位。

## 二、系统模型

```
            抄写 / 还书 / 访客事件 / 植物 / 设施每日产出
                    ↓ 流入
            ┌──────────────┐   溢出(满500)
            │  藏书厅库存   │ ─────────────→ ┌──────────────┐
            │  cap 500     │                │  自由氛围池   │
            └──────┬───────┘                │  无上限       │
                   │ 消耗                    └───┬───────┬──┘
                   ↓                             │       │
        设施升级(双消耗) / 升阶仪式        50:1兑灵感  场馆房间
```

- **阶段 = f(atmospherePeak)**，6 阶段沿用现有叙事（废墟→破败→陈旧→温暖→星辰…）
- `addAtmosphere()` 改造：库存 +X → 满则溢出自由池；`spendAtmosphere()` 新出口（库存不够时可否透支自由池=待数值定）
- 设施每日产出：结算挂在现有 tick/每日首次登录链上，离线按时间补算（有界，如最多补 24h）

## 四、借还子系统改造（决策 9 + 典藏回报）

- `state.books[bookId].borrowCount` 新字段（migration 默认 0）
- `getDamageChance(borrowLevel, hasCareSignboard, wearCount)`：基础 × 借阅区减免（下限随基准） + 磨损加成，典藏版仍免疫
- 书卡/详情显示**书况**（磨损次数或星级），重抄按钮旁提示「重抄可恢复书况」
- 典藏版还书：`returnCoins ×2 + returnAtmo ×3`，配专属访客台词（与 visitor-book-review-notes 联动点）

## 五、老存档迁移（决策 8）

- `atmospherePeak` = 迁移时当前 atmosphere 值；阶段按 peak 映射
- 已购设施等级保留，一次性加成 = Σ(各级标准值) 入库存（溢出转自由池，写入历史记录告知玩家）
- 每日产出自迁移日起算；`borrowCount` 无从追溯，存量书默认 0（老书「免磨损」作为隐性元老福利）
- 赠「开馆元老」成就 + 限定称号（成就系统改造后挂图标）

## 六、被吸收的 venue 方案要点（原文档归档不删）

- 四个场馆房间：茶室（访客羁绊事件）/ 温室（植物联动）/ 庭院（现实日历活动日）/ 档案室（馆史）
- `settleVenueMaintenance()` 每日结算房间维持费（走自由池）
- 自由池 50:1 兑灵感
- 以上全部并入本文档实施范围，`_todo-index` 对应条目标已吸收

## 七、实施阶段

1. **Phase 1 核心模型**：双池 + peak + spendAtmosphere + addAtmosphere 改造 + UI 顶栏双池展示
2. **Phase 2 设施三项**：双消耗升级 + 一次性加成 + 每日产出结算
3. **Phase 3 升阶仪式**：仪式入口 + 修缮任务链（含设施等级环节）+ 阶段只进不退
4. **Phase 4 借还改造**：borrowCount + 磨损 + 重抄清零 + 典藏回报 + 书况 UI
5. **Phase 5 场馆房间**：四房间 + 维持结算 + 50:1 兑灵感
6. **Phase 6 迁移与纪念**：老档迁移 + 开馆元老成就
- 每 Phase 独立可部署；数值表实施前跑一轮收支测算脚本
