# 大书库视觉优化计划（bookshelf-visual-optimization）

> 立项：2026-09-07，图南拍板入库。
> 动机：大书库是玩家停留时间最长的页面之一，但目前是「白底卡片网格」，与缮写室/借阅区/修复室
> 已有的场景化视觉（library_readingarea、restoration_lvX 按等级换图）不在一个水准线上。

---

## 一、现状盘点

已有（不必重做）：
- 封面系统：`visual/book_covers/book_XXX.png` + fallback 色块（bookshelf.js:378-394），26+31 本封面已入库
- 筛选栏（类别/状态）、拖拽调整位置、章节列表、阅读页、mastery 弹窗
- 书架扩容购买（300×2ⁿ 封顶 4800）

短板：
1. **无场景背景**：整个页面 parchment 卡片里直接铺网格，没有「置身书库」的空间感
2. **无书架隐喻**：买的是「书架」但视觉上是卡片墙，书与书之间没有隔板/层板关系
3. **空态简陋**：新书架空位只是空白格子；全部完成时有彩蛋但平时缺乏惊喜
4. **受损书无视觉**：灾难系统上线后（鼠患/霉斑/火灾），受损书只有文字标记，可叠加咬痕/霉斑视觉
5. **与氛围阶段零联动**：图书馆升到星辰阶段，书库长得还和废墟期一样

## 二、方案方向（分优先级）

| 优先级 | 项 | 内容 |
|---|---|---|
| P1 | 场景背景 | 按**书架数量或氛围阶段**切换书库背景图（参考 restoration 的 lv0-lv5 六图模式），废墟期昏暗木质、星辰期通透金光 |
| P1 | 书架层板视觉 | 把网格包进「书架单元」：层板 + 书立效果，封面以书脊/封面混合排布（封面网格保留为可选视图） |
| P2 | 受损书视觉 | 受损书封面叠加 啃痕/霉斑/焦痕 角标或滤镜，修复完成后消失（与 disasters.js 的 damaged 状态联动） |
| P2 | 空位插画 | 新书架空位显示虚线轮廓 + 「等待新书」小插画，引导购买/誊抄 |
| P3 | 分类色带/书脊色谱 | 按类别给书脊底色色谱条，视觉导航 + 收藏感 |
| P3 | 入场微动画 | 上架时书滑入位（复用现有动画注册表，不走视频重资源） |

## 三、素材生产

- 书库背景图：6 档，AI 生成（Maker 生图或 Seedance 首帧+图生视频截帧），风格锚定 parchment/wood/amber 金调
- 受损 overlay：鼠啃痕/霉斑/焦痕 3 张小 PNG（透明底），可程序化叠加在任意封面上
- 层板/书立：CSS 渐变即可，不必出图

## 四、待决策

1. 视觉主方向：**实景书架**（层板+书脊，沉浸但封面辨识度下降）vs **封面墙+场景背景**（保封面、加氛围）——影响 P1 的工程量分配
2. 背景切换维度：按书架数量（成长感）还是氛围阶段（世界观一致）？借阅区用的是等级，修复室用的是等级，倾向**书架数量**
3. 受损书视觉是否区分灾种（啃痕/霉斑/焦痕三套）还是先统一一个「受损」标
4. 封面网格视图是否保留为切换项（老年人玩家/小屏友好）

## 五、验收标准

- [ ] 书库有按档位切换的场景背景，废墟期 vs 星辰期观感可区分
- [ ] 受损书在书库中一眼可辨（视觉或角标），修复后恢复
- [ ] 移动端不溢出、不堆叠混乱（延续 08-28 响应式口径）
- [ ] 不破坏拖拽/筛选/阅读入口等现有交互
