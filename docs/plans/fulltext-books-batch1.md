# 全文入库「实时对应」批次一：图书馆指南 / 东京梦华录 / 诗经

> 2026-09-16 立项。目标：三本书正文全文入库，誊抄进度的每个字都对应页面上真有的字。
> 先例：book_011《道德经》80292e9（唯一现存的实时对应书，本批次照它的标准做）。

## 一、目标与范围

**做（数据层）：**
- 三本书 `content` 全文入库；`words` / `totalWords` / `unlockAt` 全部按**实际字数**回填，声明数以实际为准（不留虚数，如同道德经 5162→3468）
- 章节 `preview` / `highlight` / `previewEn` 随新内容更新
- `certMessage` / `description` 检查，不再虚称字数

**不做（本期）：**
- 缮写室展示层改造（quote 卡、writing 动画**已经在读 content/preview**，全文入库后自动获益，无需改代码）
- 其他 67 本书的节选改造（后续批次再说）

**字数口径（单一标准）：** 非空白字符计（含中文标点，不含空格/换行），与
`scripts/audit-book-word-counts.mjs` 及道德经先例一致。验收 = 审计脚本输出 `exact ✓`。

## 三、实施流水线（本批次做完后即为后续批次的标准工艺）

1. **取材**：公版文本（来源见 D1）→ 清洗：删序/注/校勘记，保留通行标点，统一全角
2. **入库**：写入 `data/books/book_xxx.js` 的 `content`（维持内联，零架构改动；
   注意模板字符串转义：反引号、`${`）
3. **回填**：新增 `scripts/backfill-book-words.mjs`——读 book 文件 → 逐章实际字数、
   累积 unlockAt、合计 totalWords → 默认输出报告，`--write` 直接改写文件（自动 `.bak`，
   git diff 审阅后提交）
4. **preview/highlight 更新**：preview 取每章开头 ~60 字；highlight 选金句
   （诗经选名篇名句，梦华录选繁华盛景句）；`previewEn` 照译
5. **文案检查**：certMessage/description 字数虚称清零
6. **存档兼容**：章节解锁是 `copiedWords` vs `unlockAt` **动态推导**（book-utils.js:76），
   无持久章锁 → 改数值对进行中书籍的章节观感有变（进度比例、当前章可能跳），
   已完成书（status=completed）不受影响；已解锁章节不会回锁数据，仅显示随阈值重算。
   图南自档若正在抄这三本，刷新生效时会有章节跳动，属预期。
7. **验收清单**：
   - `node scripts/audit-book-word-counts.mjs` 三本书 `exact ✓`
   - `npm run check:imports` 全过
   - 游戏内试玩：新档誊抄（章节解锁文案/进度条/完成证书）、大书架 writing 动画走真文
