# 氛围 v4「EXP 模型」· 第三轮评审（机制 & 数值）

> 评审日期：2026-09-08，针对 **v4 定调稿**。本轮已**实跑** `scripts/simulate-atmosphere-economy.mjs` 复现 plan 结论。
> 核验锚点：三套 stage 阈值实现 / disasters.js / focus-orchestrator.js / 灵感收支全链路。

---

## 结论先行

**v4 是对的，明显优于 v3，建议采纳。**

它最大的价值不是"数值调好了"，而是**换了范式去消解问题**，而不是打补丁。我第二轮提的四个问题因这次转向**自动消失**：

| 二轮问题 | v4 如何消解 |
|---|---|
| P0-4 火灾扣氛围 → 花光库存可免疫 | 罚金改扣金币，EXP 不掉 ✓ |
| P0-12 每日产出是冗余的第二套产能 | 涓流仿真证伪，直接不采用 ✓ |
| P1-5 维持费让场馆变负资产 | 自由池不存在，房间改金币建造 ✓ |
| P1-9 双消耗占比公式无法落地 | 双消耗整个作废 ✓ |

外加三个工程红利：**老档迁移近零成本**（纯换表、无存档结构变更，对比 v3 的 4 个新字段 + migration）、**Phase 从 6 期瘦到 4 期**、**Phase 1 半天工作量**。这是"用最简机制实现最大乐趣"的正面案例。

**但有两处 P0 会让 Phase 1 出 bug、让长线留存受损，必须先处理。**

## 一、P0-A　换表要改三处，不是一处（"半日工作量"是低估）

plan §三.1 只点名 `data/atmosphere.js`。但代码里有**三套独立的 stage 阈值实现**：

| # | 位置 | 形态 | plan 是否提及 |
|---|---|---|---|
| 1 | `data/atmosphere.js` `ATMOSPHERE_STAGES` | min/max 范围表 | ✅ 提到 |
| 2 | `js/core/economy.js:7-11` `getAtmosphereLevel` | 硬编码 30/80/160/300/500 | ❌ **漏** |
| 3 | `js/collection.js:73-79` `getAtmosphereStageLevel` | 硬编码 30/80/160/300/500 | ❌ **漏** |

- **#2 才是驱动升阶检测的那个**：`storage.js:48/50` 在 `addAtmosphere` 里比对 `prevLevel`/`newLevel` 触发 `atmosphere_upgrade`。
- **#3 驱动收藏品里程碑**（`collection.js:86-88`）。
- **只改 #1 的后果**：玩家氛围 300 时场景/描述按新表是 **2 阶**，但收藏品页仍用旧表 `value<=300 → return 5`，会显示 **「星辰」**。**这是必然 bug，不是隐患。**

**建议**：合并为单源——在 `data/atmosphere.js` 导出 `getStageLevel(atmosphere) → { level, stage }`，三处统一 import。顺带把 Phase 1 工时重估为 1-2 天（含 9 个调用点回归）。

> 附：换表还有一个**隐性连锁**——`disasters.js:123` 霉菌概率读 `getAtmosphereStage()`，`stageFactor = max(0.1, (6 - level)/5)`。同一氛围值在新表下**阶段更低**（氛围 100：旧=3阶 → 新=1阶），factor 从 0.6 → 1.0，**前期霉菌概率上升约 67%**。要么接受，要么给霉菌改用独立的 absoluto 阈值。

## 二、P0-B　节奏曲线是「平台后断崖」，不是平滑递增

实跑仿真（`node scripts/simulate-atmosphere-economy.mjs --verbose`）**复现了 plan 的 173/207/254**，数字可信。但拆开看阶段停留：

| 段 | 硬核 | 核心 | 休闲 |
|---|---|---|---|
| 1→2 阶 | 12 天 | 15 天 | 18 天 |
| 2→3 阶 | **10 天** | 13 天 | 29 天 |
| 3→4 阶 | **53 天** | 65 天 | 71 天 |
| 4→5 阶 | **98 天** | 114 天 | **136 天** |

**两个异常**：
1. **节奏倒挂**：2→3 阶（10 天）比 1→2 阶（12 天）还短。
2. **末段失控**：4→5 阶 98 天，占总时长 **57%**；休闲 **136 天**（4 个半月）。

### 根因：门槛解锁的等级与产能台阶错位

`returnAtmo` 表（borrow-levels.js）= **1/1/3/3/5/5/5**（Lv1-7）
`stageFacilityGate` 表 = stage2→Lv3 / stage3→**Lv4** / stage4→Lv5 / stage5→**Lv6**

- stage3 解锁 Lv4：returnAtmo **3 → 3，零产能提升**（无效台阶）
- stage5 解锁 Lv6：returnAtmo **5 → 5，零产能提升**（无效台阶）

所以 stage3 之后**没有产能台阶可爬**，只能靠存量硬堆 → 53 天、98 天的两段空窗。而 §〇 明确写着「阶段达到阈值自动升级，**升级解锁新内容**」——**3-4 个月没有任何阶段级解锁**，这是留存杀手级的反馈空窗。

### 建议（任选，推荐 A）

- **A（推荐）**：`returnAtmo` 改为每级递增 **1/2/3/4/5/6/7**，让每次门槛解锁都带来真实产能提升——最自然，且符合"借阅区越高级还书收益越高"的既有直觉。
- **B**：gate 表对齐产量台阶，跳过 Lv4/Lv6 这两个无效档。
- **C**：4→5 之间插入**里程碑**（非完整阶段，但给奖励 / 内容预告）——放置类标准做法。
- **无论选哪个**：建议把 5 阶阈值从 6500 下调，把末段时长匀给中间档，目标形状 15/30/50/78 而非 12/10/53/98。

## 三、P1 应改项

### P1-C　35% 的 EXP 来自"买设施"，核心玩法被稀释

- 终态样本（借阅区Lv6 / 缮写室Lv6 / 修复室Lv5）：设施 EXP = 40×(1+..+6)×2 + 40×(1+..+5) = **2280**
- 占总需求 6500 的 **35%**
- 而硬核金币**结余 39402 ≈ 消耗的 1.85 倍** → 后期金币过剩，设施是"顺手买"

**风险**：玩家体感"我买设施比专心抄书升级快"，稀释核心玩法（专注 / 抄写）的价值——而核心玩法才是这游戏真正的乐趣载体。

**建议**：设施 EXP 降到总量 **15-20%**（每项改 `等级×20`，或改为"仅每座设施**首次**购买给"）；若 35% 是刻意设计（金币→EXP 转换通道兼作金币 sink），请在文档写明占比预期，别让它成为默认值。

### P1-D　金币过剩存在严重阶层分化，新消费口难定价

| 画像 | 金币消耗 | 金币结余 | 结余/消耗 |
|---|---|---|---|
| 硬核 | 21,271 | **39,402** | 1.85× |
| 核心 | 21,271 | 19,745 | 0.93× |
| 休闲 | 21,271 | **1,104** | 0.05× |

**休闲几乎花光，硬核剩近 4 万。** plan §五 说"需要 2-3 个新金币消费口"是对的，但**单一价位必然两头不讨好**：面向休闲定价 → 硬核瞬间买完继续过剩；面向硬核定价 → 休闲买不起。

**建议**：消费口分层——① 便宜高频消耗品（面向全体，持续回收）② 昂贵收藏/装饰/限量（面向硬核，做 sink 深度）；场馆房间应做多档定价而非单档。

### P1-E　灵感：被仿真低估约 3.5 倍，且 v4 删除 50:1 后无替代 sink

- 脚本 `inspirationPerDay: 2`。实测灵感 faucet：
  - `dailytasks.js:52` **+3/日**
  - `focus-orchestrator.js:58` 烛台 **+1**；`:65/68` 沙漏（≥60min）期望 **+0.35**；`:77` 连击期望 **+0.15~0.25**
  - `book-progress.js:135` +1、`plants.js:309` +item.value
  - → 硬核（2.5 次专注/日）实际约 **7/日**，是脚本假设的 **3.5 倍**
- 消耗端（sink）只有两个：`book-progress.js:172` 重抄 **-1**、`dlc-packs.js:104` DLC 购买
- 净积累约 **+6.6/日 → 年 ~2400 灵感**（脚本只显示 294）

**判断**：v4 删除 50:1 兑灵感**方向是对的**（那其实是灵感的 faucet 而非 sink），但删完**没补 sink**。若灵感真按 7/日 流入，DLC 售卖会在数月内被买穿，失去长线意义。

**建议**：① 把脚本 `inspirationPerDay` 校正为实测值重跑；② 为灵感补一个**持续** sink（如灵感购��ja特邀检索 / 限时装帧），而非只有一次性 DLC。

### P1-F　第二阶段后才能碰设施：新手期 ~12 天设施锁死

`stageFacilityGate` 无 stage1 项 → `|| 1` → **stage 1 期间设施最高 Lv1**（初始 borrowLevel=0，即只能升 1 级）。而这 12 天 returnAtmo=1、产能最低。

新手最需要的"我变强了"的正反馈，恰恰在这 12 天被完全锁死。**建议** gate 表补 `1: 2`，让新手期至少买到 Lv2。
