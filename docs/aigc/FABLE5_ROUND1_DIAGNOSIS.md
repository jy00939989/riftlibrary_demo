## P0 叙事诊断核心结论

### 人设诊断总评
**底子是好的**——10人覆盖年龄/阶层/性别/困境类型，"普通人+一个执念"结构正确。
**问题不在人设，在执行层。**

### 重写优先级 Top 3
1. **王小磊**（文学上限最高 + 机制叙事绑定最深 + 截图自传播潜力）
2. **程远**（目标用户的镜像角色，共鸣ROI最高）
3. **沈明远**（终局赠书是最重情感机制 + 新玩家第一印象）

### 语言五大病灶
1. 情感直给（"我很感动"→藏在动作和物件里）
2. 声音同质化（遮住名字认不出谁在说话）
3. 金句依赖（条条都想升华）
4. 书与人脱钩（谈书不谈生活）
5. 缺少"未说完的话"（没有钩子让玩家期待下次）

### 三层叙事写作纪律
- **常层**：对书说话，克制，几乎不暴露自己
- **偶层**：对你说话，第一次出现私人名词（我妻子/我儿子/我老家）
- **稀层**：对自己说话，把从没说过的说出来，你只是恰好在场
- **终局**：为你做一件事，语言退场行动登场

### 十句声音锚点（Voice Anchor）
- 沈明远："这句话我年轻时读不懂，现在懂了，倒希望自己没懂。"
- 程远："代码能回滚，三十九岁不能。"
- 裴舟："这本书卖出去过三次，退回来两次，第三次没人还。"
- 简安："兹证明——算了，这句话我留给小说。"
- 江有树：满句"也许""大概"，偶尔一句异常笃定
- 谷雨：具体名词 + 真诚感叹号（不是修辞，是真的）
- 乔一一：贬低开头，真心藏在从句里
- 谢如归：给感情记账——"陪伴这种东西，复利效应被严重低估了。"
- 夏蝉：用练习室单位计量人生，把失败说成"排练"
- 王小磊：地址、楼层、面单入诗

## R3：数值平衡（3.5）+ 游戏性（A）+ 可玩度（B）+ 可行度（C）+ 商业化（D）+ 运维（E）

### 3.5 数值平衡：四个问题的具体解法

**① 字数跨度（2,500 ~ 860,000）**：不是平衡问题，是内容形态问题。86万字的西游记按任何合理速率都是数百个番茄钟，无中途正反馈=弃坑加速器。

- **分卷成书**：西游记 → 4卷，每卷独立结算。红楼梦、史记、几何原本同理。
- **选抄本 + 全本双轨**：默认卖精选抄本（约全本 8-10%，2-3周完成），全本作为 mastery Lv5 后解锁的长线声望内容。把大书从"新手劝退项"变成"老玩家荣誉项"。
- **设计基准**：以番茄钟数为唯一单位——短书 1-3 钟、中书 8-15 钟、大书每卷 20-30 钟。

**② 访客概率公式验证**：写 `tools/simulate.js`（Node 跑，无浏览器依赖）。3个玩家画像 × 90天 × 1000次蒙特卡洛。验收红线：中度玩家 ≤3天见到第一条偶层、≤21天见到第一条稀层。超线就调概率。这是本节 ROI 最高的一件事，前提是把奖励公式抽成 `js/core/economy.js`。

**③ 智慧之光通胀**：先测后堵。消耗出口按优先级：位面盘缠（改动最小）→ 馆藏修复（与废墟主题自洽）→ 声望捐赠（装饰性消耗，最健康的无限出口）。

**④ 商店定价**：换成"天数本位"——中度玩家 Lv1 ≈ 半天到1天，最高级 ≈ 10-14天。超过两周的单项目标必须拆中间里程碑。

### A. 游戏性

**核心问题**：玩家只有一个主动动词。专注→奖励→购买是"挣钱花钱"，访客/还书/叙事全是被动到来。

- **策展升格为叙事触发器**：特定策展组合吸引特定访客、触发专属评论。给 `curation_pairs` 加 `visitor_comment` 字段。这一步把三个孤立系统焊在一起。
- **协同短板**：植物/标志牌/策展都是 buff 贴纸。焊接方案——谷雨评论植物、裴舟评论策展、访客提及标志牌。访客是所有系统的"见证人"。
- **内容天花板**：不做 prestige 重置（叙事收集型玩家极其厌恶清空回忆），做**新访客季更**。一次更新一位新角色，匹配 itch.io devlog 曝光机制和变现方案。

### B. 可玩度

- **引导过载**：PV+3步+10步+情境教程四套叠加。建议压到6步，把"抄完第一本短书 + 第一次还书触发叙事"提前到前3步——差异化钩子是叙事，必须前10分钟让玩家尝到。
- **每日时长红线**：任何奖励都不能诱导"假专注"。72小时植物凋谢→休眠（浇水复活），惩罚缺勤对生产力工具是自伤。
- **重复劳动反馈**：专注进行中屏幕上逐行浮现真实书籍内容，把"番茄钟等待"变成"看着东西长出来"。

### C. 实现可行度

纯前端唯一硬缺口是云存档（有轻量绕行方案）。**永久放弃 Godot**，路线定为 **Web → Tauri(Steam) → Capacitor(移动)**——一套代码三个渠道。这才是纯前端的复利。

### D. 商业化

- **用户画像**：20-35岁中文互联网学生/考研考公党/知识工作者，番茄钟重度用户 × 文字审美型玩家交集。愿意为"情感体验"付费，极度反感广告和氪金焦虑。
- **竞品**：Forest（习惯工具）→ 你是情感陪伴；心流小筑（国风治愈）→ 它无角色叙事。**10个活人是唯一且足够的护城河**。
- **变现路线**：Now → PWYW + Supporter Pack（$3-5：OST+壁纸+诗笺集PDF+夏蝉歌词手稿本PDF——**叙事重写自动变成周边素材**）；3-6月 → Patreon 月更角色订阅；6-12月 → Steam 买断（Tauri，$4.99-6.99）。
- **永远不做**：广告、体力值、抽卡。一次都不能碰。

### E. 运维

- **消灭 deploy 分支** → 单 main + GitHub Actions。push → build → 产物同时推 Netlify + EdgeOne。发版打 git tag。
- **localStorage → IndexedDB**（idb-keyval，~1KB库）：容量 5MB→几百MB，写入不阻塞主线程。saveState() 几十处高频调用在 localStorage 上是同步 IO，隐性卡顿源。
- **存档结构加 schemaVersion + 迁移函数链**（v1→v2→v3），每个迁移配真实旧档测试用例。state.js 迁移逻辑是全项目唯一"坏了就永久失去用户"的代码。
- **监控三件套（全部免费档）**：Sentry（JS 错误上报）→ Smart Quote 事件 5 分钟发现；Umami/Plausible（隐私友好，无 Cookie）→ 四个关键埋点：引导步骤完成、首次还书、首条偶层触发、第7天留存；构建体积哨兵（size-limit）→ 首屏超过 300KB gzip 报警。

## F. 代码健壮度

**核心病灶**：2.6万行纯前端最大的定时炸弹是 `window.render*` 全局函数网——"改A处炸B处"的隐性耦合（Smart Quote事故即为此病发作）。

**四层药方（按ROI排序）**：

1. **抽纯函数层**（最高优先级）：把所有"输入状态→输出数字/结果"的逻辑从渲染和DOM里剥出来，集中到无副作用的模块：
   - `js/core/economy.js` — 奖励结算、访客概率、定价
   - `js/core/narrative.js` — 叙事条目抽取、好感门槛、去重逻辑
   - `js/core/state.js` — 存档读写 + 迁移链
   - 判定标准：函数能不能在 Node 里、没有 window 的情况下跑出正确结果？能，就进 core/，配单元测试。

2. **state.js 迁移链是全项目唯一"坏了就永久失去用户"的代码**：每个历史版本存一个真实旧档 JSON 当 fixture（`tests/fixtures/save_v1.json ... save_v7.json`），逐档跑迁移，断言不丢字段不崩。每次发版前 CI 必须绿。

3. **事件系统 schema 校验**：访客/叙事条目加运行时校验（加载 visitor-events.js 时跑），字段缺失/概率超范围/好感门槛非法，开发环境直接抛错。AI 改文案手滑删掉一个 weight 字段，当场拦下。

4. **工程护栏**（防 Smart Quote 复发）：CI 加 lint + 冒烟测试（headless 启动游戏→跑完新手前3步→还一次书→断言无 console.error）。AI 只允许动 books/、data/文案等纯数据层，core/ 改动必须人工 review。

## G. 视觉美化

六个未做但性价比极高的方向：

1. **墨墨微表情/待机动画**：全项目 ROI 最高的单处美术——它出现在每一次叙事高潮里。眨眼、听歌时头部微转、评审通过时翅膀尖动一下。纯 CSS/精灵图可实现。

2. **氛围5阶段的"环境增量"**：不仅靠色调，每阶段加可辨认的场景增量——灰烬期光秃书架→复苏期第一株藤蔓→繁荣期光尘在光柱里浮动。玩家要能"一眼看出馆升级了"。

3. **数值飞字 + 计数器滚动**：智慧之光/氛围+X 时加飘字动画 + 顶栏数字 count-up。番茄钟的正反馈全靠微交互堆。

4. **访客到场/离场仪式**：推门/身影渐入 + 专属代表色/剪影 + 一句浮现的台词气泡。没有立绘也能有辨识度。

5. **声音层**：翻页声、墨墨轻鸣、番茄钟完成音、誊抄笔尖沙沙。专注类产品沉浸感一半在氛围音。可选开关 + 5-6个音效文件。**你已有 6 个 SFX + BGM 系统，基础设施完备，只需加文件。**

6. **17.8MB 图片资产工程化**：转 WebP/AVIF、按氛围阶段懒加载、雪碧图合并小图标。首屏只加载当前阶段资源。

## H. 创意发散

**约束原则**：任何新功能必须服务"专注工具"本职，不能变成为玩而玩的负担。

1. **访客×访客相遇事件**（几乎零新系统）：夏蝉×乔一一"想被看见 × 想逃离被看见"——做成稀有双人事件。10 角色两两组合是巨大内容池，只需写文本、复用现有框架。最低成本抬高内容天花板。

2. **叙事道具陈列室**：王小磊诗笺、夏蝉歌词本、终局馆藏——"角色留下的实体"系统化。可翻阅、可摆放。对接变现（陈列品=周边素材）。

3. **墨墨成长线**：随馆龄增长极淡的暗线——透露来历、对某些书有反应、深夜有专属台词。它是玩家的长期陪伴者。

4. **位面"回信"做成慢速笔友**：玩家寄出书/抄本→几天后收到手写回信+对方世界碎片。反催促，契合专注气质。同时是智慧之光消耗出口。

5. **季节/时令联动**：读取真实日期，馆内随季节变化（落叶、初雪、应季书自动策展推荐）。零玩法负担，纯氛围复利，制造"每个季节想回来看看"的软留存。

**一个要克制的诱惑**：不要加战斗、不要加竞速排行、不要加体力值。全部朝"更安静、更慢、更有陪伴感"走。

## I. 实际工作流

1. **内容与代码物理分层 + 分权限**：
   - `data/`、`books/`、文案 → "内容层"，AI 可自由改
   - `js/core/` → "逻辑层"，只能人工改，PR 必须 review
   - 规则写进 AI system prompt：AI 默认只有内容层写权限。这一条挡掉 80% 历史事故。

2. **叙事文本"评审→入库"流水线**：文案用结构化格式存（id/tone/好感门槛/权重/文本），写 validate-content.js 跑 schema + 统计（感叹号密度/"继续再来一遍"出现次数——铁律直接编码成 lint）。入库走 PR，CI 自动跑。

3. **单 main 分支 + tag 发版**：消灭 deploy 分支。日常在 main 上开 feature 短分支，合并即部署预览，打 tag 即正式发版。发版 CI：迁移测试 + 冒烟测试 + 内容校验 + 构建体积，四项全绿才允许 tag。

4. **AI 协作安全操作规程**：
   - 改动前先说清改哪些文件、为什么，确认后再动
   - 禁止跨层批量替换（Smart Quote 根因）——全局改动必须逐文件 diff review
   - 每次 AI 大改前，人工 git commit 干净存档点

5. **内容更新节奏**：每月一位新访客 = 一个内容层 PR（visitor-events + 立绘/色卡 + changelog）。发版时墨墨在游戏内报幕。工作流+变现+叙事仪式感三合一。
