# 位面系统测试反馈（2026-05-21）

> Phase 1 框架搭建完成后首次测试，记录三个待解决的问题。

---

## 问题 1：传送门购买与升级模型

**现状**：位面商店中的传送门在满足解锁条件（氛围≥80 + 拥有≥12本书）后，需要花费智慧之光购买。购买后传送门消失，无法继续升级。

**期望**：

- 传送门购买后，在位面商店保留入口，显示"已解锁"
- 后续版本中，传送门可升级（如 Lv.1→Lv.2），升级后解锁更多位面
- 升级可能需要更高氛围值 + 更多书籍 + 智慧之光
- 例如：田园传送门 Lv.1 解锁田园位面，Lv.2 解锁下一个位面

**影响范围**：`js/shop.js` 购买逻辑、`js/render/shop.js` 传送门 UI

**优先级**：🟡 建议 Phase 2 实现

## 问题 2：誊抄章节任务无法精确完成

**现状**：小艾拉第一个任务要求"誊抄《小王子》第三章"（`condition: { bookId: 'book_001', chapterIdx: 2 }`）。但当前誊抄系统的设计是：专注时累计字数，按字数解锁章节（自动连续解锁），玩家**无法选择誊抄特定章节**。

**当前实现**：`checkTaskCompletion('chapter_unlocked', ...)` 监听章节解锁事件。章节解锁是按字数阈值自动触发的连续过程——解锁第1章后，第2章和第3章会随着字数增加依次自动解锁。这意味着玩家只要持续专注誊抄《小王子》，第3章终会被解锁，任务会被动完成。

**问题本质**：任务"誊抄特定章节"的设计与系统"按字数连续誊抄"的机制不完全匹配。玩家缺乏"我专门在誊抄第三章"的主动感。

**可能的解决方案**：

- **方案 A**：保持现状（设计评审推荐的宽松方案），`chapter_unlocked` 即视为完成。玩家正常专注誊抄，章节自然解锁即完成任务。优点是零开发成本，缺点是缺少主动选择感。
- **方案 B**：在缮写室 UI 中增加章节选择功能，让玩家可以"当前专注于第N章"。字数只计入该章节。
- **方案 C**：将任务类型从 `copy_chapter` 改为 `read_chapter`（阅读指定章节），利用已有的阅读弹窗（`bookshelf.js` 中的章节阅读功能）完成任务。

**建议**：短期用方案 A（Phase 1 框架验证阶段可接受），长期考虑方案 B 或 C。

**影响范围**：`js/quests.js` 任务判定逻辑、`js/render/focus.js` 缮写室 UI（方案 B）

**优先级**：🟡 建议 Phase 2 前确定方案

## 问题 3：位面角色到访缺乏"出场感"

**现状**：购买传送门后，下一个 60s tick 触发 `tickPlaneVisitors()`。如果小艾拉此前没有活跃任务，系统立即分配第一个任务并设置 `met = true`。这个过程中：

- 小艾拉**没有出现在读者沙龙**的访客列表中
- 小艾拉**没有浏览行为**（借书/还书/事件）
- 玩家在角色卡片中看到"已到访"和第一封信，但从未在图书馆中"见过"这个角色

**设计审查的建议**：审查报告明确指出位面访客队列应独立于普通访客（`visitors.js`），避免位面角色参与借书/还书/事件系统。但完全隔离也导致了"角色在后台静默到访"的问题。

**可能的解决方案**：

- **方案 A**：首次到访时在右下角弹出访客到来卡片（复用 `showVisitorArrivalCard`），让玩家感知"有人来了"
- **方案 B**：位面角色首次到访时，在读者沙龙短暂出现（`status: 'browsing'`），但跳过借书/还书逻辑，仅展示"{{name}} 在书架间徘徊，留下了一封信"
- **方案 C**：在购买传送门后的首次专注完成时，触发"传送门发光"事件 + 角色到访动画，作为一次性叙事触发

**建议**：方案 A 投入最小，可立即实施；方案 C 叙事效果最好，适合 Phase 2 打磨。

**影响范围**：`js/quests.js` 的 `tickPlaneVisitors`、`js/app.js` 的访客卡片展示

**优先级**：🔴 建议 Phase 1 内修复（方案 A）
