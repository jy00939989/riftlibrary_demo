# 氛围来源收窄实施计划（atmosphere-source-narrowing）

> 目标：把"到星辰之境（氛围 500）太快"的进程拖慢，且不破坏现有叙事/成就/UI。
> 范围：纯数值收窄，不改 state 结构、不加新系统、老存档自动生效。
> 配套设计：根本解是 `docs/plans/atmosphere-venue-map-design.md` 的双池 + 房间 sink；本计划是**过渡期止血**，先把单池里偏高的来源砍下来。

---

## 一、为什么做（Context）

- 氛围当前是**单池 `atmosphere`，硬封顶 `Math.min(500, …)`**（`js/storage.js:49`）——攒满后所有氛围来源变废纸。
- 全代码库 `addAtmosphere` 共 32 个调用点，其中 4 类是"到星辰之境太快"的主要加速器：
  1. **抄书（含重抄）氛围**——每次誊抄都发，频率最高、无上限。
  2. **稀层（rare）事件氛围**——单次 30/40，全角色全触发 ≈ 700 点，超整条星辰条。
  3. **访客归还基础氛围**——每次还书都发，随借阅区等级涨到 Lv7=8。
  4. **植物收获氛围**——星光蕨 45/茬，重复种 ≈ 450/月。
- 偶层（occasional）事件只有 3–8 氛围，一次性有界，**非主要 culprit**，本计划保持不动。
- **本计划只针对可再生流（抄书、还书、植物、稀层事件），一次性池（成就/策展/位面等）不在范围。**

---

## 二、修正声明（对前次 audit 的勘误）

前次氛围审计将 `30/40` 误归为 occasional（偶层）。实测 `data/visitor-events.js`：

- `occasional`（偶层）：每条 3–8 氛围，每角色约 5 条，一次性 → **总量约 190 点，非大头**。
- `rare`（稀层）：`reward: { atmosphere: 30, coins: 60 }` / `{ atmosphere: 40, coins: 80 }`，全角色共 **10 对（30+40）**，一次性但总量 **≈ 700 点** → **这才是单次最大的氛围块**。

本计划 §四-2 砍的是**稀层**，不是偶层。

---

## 三、目标（Goals）

1. 砍掉抄书重抄的无脑氛围。
2. 稀层事件氛围 30/40 → 10/15。
3. 借阅区归还基础氛围高段封顶（Lv7 不再涨）。
4. 植物收获氛围 25/45 → 10/15（鹤望兰 2 不动）。
5. 保持向后兼容，不破坏旧存档。

---

## 四、四项改动（逐项：现状 / 代码位置 / 新值 / 理由 / 风险）

### 改动 1 · 抄书重抄氛围 → 仅首通发放

| 项 | 内容 |
|---|---|
| 现状 | `js/core/book-progress.js:77-79`：`addAtmosphere(Math.floor(atmoReward))` 在 `isFirstCompletion` 判断**之前**无条件执行，每次誊抄（含重抄）都发。短书 3 / 中 6 / 长 10（单卷 ×0.5）。`:89` 之后才是 `if (isFirstCompletion)` 块，用于发币/解锁/首通成就。 |
| 新值 | 氛围按首通/重抄区分：首通全额，重抄 ×0.5。实现方式：**删除 `:79` 的无条件发放**，改成如下一段（放在当前 `:77-79` 位置）：<br>```js<br>const mult = isFirstCompletion ? 1 : 0.5;<br>addAtmosphere(Math.floor(atmoReward * mult));<br>addCoins(Math.floor(coinReward));<br>```<br>这样不依赖 `:89` 的 `if` 块顺序，避免双发。 |
| 理由 | 氛围语义是"首次修复里程碑奖励"，但重抄作为熟练度复训仍应保留一点里程碑感。×0.5 既砍掉重抄无脑刷氛围的主要动力，又避免玩家觉得重抄"完全没劲"。 |
| 风险 | 低。重抄仍有币激励 + 半数氛围，玩家刷分动力不受影响；相比全额重抄，整体氛围产出已降低约 50%。 |
| 备选 | 若后续数据仍显示星辰进度偏快，可进一步把重抄氛围砍到 0。 |

### 改动 2 · 稀层（rare）事件氛围 30/40 → 10/15

| 项 | 内容 |
|---|---|
| 现状 | `data/visitor-events.js` 每个角色 `rare` 含两条：`reward:{atmosphere:30,coins:60}` 与 `reward:{atmosphere:40,coins:80}`。全角色共 10 对（行号：74/81、182/191、266/275、346/355、456/465、566/575、675/684、786/795、924/943、1060/1069）。 |
| 新值 | 全部 `30 → 10`、`40 → 15`；**coins 保持 60/80 不变**（稀层仍"值钱"，只是不再用氛围暴击星辰条）。<br>实施方式：已核实 `atmosphere: 30` / `atmosphere: 40` 在 `data/visitor-events.js` 中仅出现在 rare 奖励，可直接整文件替换 `:30`→`:10`、`:40`→`:15`，零误伤。 |
| 理由 | 稀层全触发 ≈ 700 点氛围，超整条星辰条 1.4 倍。降到 10/15 后全触发 ≈ 250 点，约占半条。单次仍是明确的"大事件感"，但不破坏进度节奏。 |
| 风险 | 低。仅数值；触发逻辑/文案/永久效果（unlock_book / signboard）完全不动。 |
| 注意 | occasional（偶层 3–8）、常层扩容（5/10/12）**本次不动**——它们小且有界。final（终局）事件经核查不带氛围，无需处理。 |

### 改动 3 · 借阅区归还基础氛围高段封顶

| 项 | 内容 |
|---|---|
| 现状 | `js/visitors.js:369-375` `BORROW_LEVEL_TABLE`：`returnAtmo` 随等级 Lv1=1 / Lv2=1 / Lv3=3 / Lv4=3 / Lv5=5 / Lv6=5 / **Lv7=8**。`visitors.js:1074` 每次还书 `addAtmosphere(retCfg.returnAtmo)`。 |
| 新值 | Lv7 `returnAtmo` 由 **8 → 5**（即 Lv5 之后封顶，不再随等级续涨）。Lv1–Lv6 不动。 |
| 理由 | 归还氛围是最高频的持续流（每次还书）。高段（Lv7 圣所）应奖励容量/好感/币，而非继续加码氛围——否则满级借阅区让星辰条被日常还书光速填平。 |
| 风险 | 低。仅 Lv7 一项；Lv5/Lv6 已为 5，曲线自然在 Lv5 后走平。 |
| ⚠️ 注意（triplication） | `BORROW_LEVEL_TABLE` 在 **3 个文件重复定义**：`js/visitors.js:369`（运行时 `getBorrowLevelConfig` 实际读取此份）、`js/core/economy.js:9`、`js/core/visitor-lookup.js:22`。本计划只改 `visitors.js:369`（生效那份）。`economy.js`/`visitor-lookup.js` 的同表是 god-split 遗留副本，应在后续重构中合并为单源（见 §七 后续），否则将来改一处会静默 desync。 |

### 改动 4 · 植物收获氛围 25/45 → 10/15

| 项 | 内容 |
|---|---|
| 现状 | `data/plants.js`：`harvestAtmosphere` 鹤望兰=2 / 魔法玫瑰=25 / 星光蕨=45。`js/plants.js:168` 收获时 `addAtmosphere(def.harvestAtmosphere)`。 |
| 新值 | 魔法玫瑰 **25 → 10**，星光蕨 **45 → 15**；鹤望兰 **2 不动**（它是金币植物，氛围非卖点）。 |
| 理由 | 星光蕨单盆单槽、每生命周期收一次，但玩家为刷种子会反复种 → ≈ 每 3 天一茬 × 45 ≈ **450/月**直接进 0–500 池，是隐藏加速器。砍到 15 后 ≈ 150/月，且保留其"比玫瑰高"的相对定位。星光蕨"高氛围"身份靠**双池路由**（见 §七）根本解决，过渡期先压量级。 |
| 风险 | 低。收获仍有币（35/30/15）+ 种子，payoff 不空。若觉得 15 仍高，可再压到 8。 |
| 联动 | `js/plants.js:178` 的收获历史文案读取 `def.harvestAtmosphere`，数值改后自动同步，无需改 i18n。 |

## 七、后续（根本解，不在本计划范围）

- **双池 + 场馆地图**（`atmosphere-venue-map-design.md`）：新增 `venueAtmosphere`（自由池，可增可减），访客归还/植物收获在藏书厅满后自动转入此池；此池有房间解锁/维持/兑灵感等 sink。届时植物收获氛围可**改路由**而非砍数值，星光蕨"高氛围"身份完整保留。

## 八、验证（Verification）

1. 新存档：找一本**非单卷短书**连续誊抄 2 次，确认第 1 次加全额氛围（短 3 / 中 6 / 长 10）、第 2 次（重抄）**加一半氛围**（短 1 / 中 3 / 长 5）且加币。**注意：单卷书首通本身已 ×0.5，首通为 1/3/5，重抄为 0/1/2，测试时不要用单卷书断言。**
2. 新存档：连续誊抄同一本书 **5 次**，确认第 2–5 次每次都只加首通的一半（`Math.floor` 后短 1 / 中 3 / 长 5），不会出现逐次衰减或全额恢复。
3. 触发某角色稀层事件，确认氛围加成为 10 或 15（非 30/40），币仍为 60/80。

8. 跑 `node --check` 四个文件语法通过。
9. （可选）开启一个新存档按正常节奏游玩，记录从 0 到 500 氛围的实际天数，作为是否达成"拖慢星辰进度"目标的量化依据。
