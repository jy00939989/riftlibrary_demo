## ⚠️ 关键上下文（本轮优化核心）

### 1. 平台策略：坚持纯前端，目标 itch.io 发布

- 项目已有**早期用户**，并获得**正反馈**，验证了产品价值

- 当前目标：**完善纯前端版本 → 发布到 itch.io / 独立游戏平台**
- 纯前端的优势：零安装、URL即玩、跨平台、itch.io 原生支持 HTML5 游戏
- 关键问题：**"什么样的完成度才够发布到 itch.io？"**

### 2. 叙事质量：最高优先级问题

- 10位访客角色的叙事文本（`data/visitor-events.js` 1087行 + `js/visitors.js` 还书语录）目前水准不够
- 这是游戏的**核心差异化竞争力**——番茄钟工具遍地都是，但"有10个活生生的角色陪你在图书馆"是独一无二的
- 需要 Fable 5 重点评估：
  - 每个角色的人设是否足够鲜明、有辨识度？
  - 叙事文本的文学质量（语言、节奏、情感密度）
  - 三层叙事结构（常层→偶层→稀层→终局）是否发挥了应有的情感冲击力？
  - 角色之间的化学效应是否被充分利用？
  - 具体重写优先级和范例

## 二、完整系统清单

### 2.1 专注/誊抄系统

- **3种模式**：番茄钟25分钟、倒计时自定义、正计时不限时
- **进度计算**：基于书籍总字数和已抄字数，分章节解锁
- **奖励公式**：基础智慧之光 + 连击加成(2%/天) + 成就加成 + 光环加成 + 策展加成 - 速度惩罚
- **灵感系统**：连续专注7天解锁，专注结算时概率获得
- **茶boost**：行动卡触发，前5分钟速度+10%
- **烛台buff**：完成时额外+1灵感
- **缮写室升级**：6级(Lv0-Lv5)，每级+5%速度（成就加成可到7%）
- **损毁机制**：还书时~3%概率书籍损毁，损失25%已抄字数
- **重抄系统**：完成5次誊抄(mastery Lv5)解锁重抄
- **标志牌加速**："请保持安静"+1%速度，"时光沙漏"长专注额外灵感

**叙事引擎（三层递进）**：
- **常层**：每次还书必然触发（base 4-6条，expand1 +4条，expand2 +4条）
- **偶层**：好感≥30，30%概率，线性推进（5-6条/人）
- **稀层**：偶层全完成+好感≥60，10%概率，一次性剧情高潮（含永久效果：赠书/标志牌/解锁）
- **终局**：稀层触发后100%触发
- **终局后常层**：终局后每次还书可重复触发
- **终局后偶层**：终局后好感≥100，30%概率

## 三、已知问题与技术债

### 3.1 架构层面

1. **无模块循环依赖但隐式耦合严重**：app.js 直接 import 28个模块，render函数通过 window 全局暴露互相调用（如 `window.renderLibraryPage()`）
2. **state.js 臃肿**：537行纯状态定义+迁移逻辑，缺乏类型约束
3. **渲染与逻辑未分离**：render/shop.js 773行中混合了购买确认弹窗DOM操作和业务逻辑
4. **无组件化**：所有UI通过 innerHTML 模板字符串拼接，无虚拟DOM无diff
5. **ES Modules 但无打包**：浏览器原生加载，28本书各一个文件，29个HTTP请求
6. **CSS全站单文件**：1592行无scope，全局样式冲突风险
7. **无测试**：0个单元测试/集成测试

### 3.2 性能问题

1. **首屏加载**：29个book文件 + 19个render文件 + 12个逻辑模块 = 60+ HTTP请求
2. **每次renderShopPage重建全量DOM**：无增量更新
3. **计时器用setInterval 1秒**：精度低，无visibility change暂停
4. **图片未做懒加载/压缩**：visual目录17.8MB全量
5. **无Service Worker**：无法离线使用
6. **localStorage 频繁读写**：saveState() 在几十个地方被调用

### 3.3 已记录Bug

1. **Smart Quote语法错误**（2026-06-04修复）：Agent批量改写时将JS代码中ASCII引号替换为Unicode smart quotes，导致ESM加载失败。172处受影响。
2. **Netlify部署分支冲突**：deploy和master分支经常不同步

### 3.4 未完成功能

1. 访客好感度深度整合（讨论已做，实现待排期）
2. 缮写室场景化改造（Step1-5计划但未实施，已中道崩殂于Godot决策）
3. 克克小手机项目（方案已写，未启动）
4. 3个MP4视频（借阅区解锁/氛围0-1/访客初临）未接入
5. 植物系统"技术债：待改"
6. 标志牌功能页面挂载未完全实现

### 3.5 数据平衡未验证

- 书籍字数跨度极大（2500~860000），大书誊抄周期可能长达数月
- 访客到来概率公式未经数值策划验证
- 智慧之光通胀风险（缺乏消耗出口）
- 商店定价曲线未做玩家体验测试

## 四、优化目标（按优先级排列）

### 🔴 P0：叙事语言重写（最高优先级）

**现状**：`data/visitor-events.js`（1087行）+ `js/visitors.js` 中 RETURN_QUOTES + STAGE_WITNESS 构成当前全部叙事文本。开发者自评"水准不行"。

**你需要回答的问题**：
1. **逐角色诊断**：对10位角色，逐一分析其人设是否成立、是否与光环/偏好/叙事文本自洽、是否有辨识度（读者能否仅通过文本认出这是谁在说话）
2. **语言质量评估**：当前叙事文本在文学性（节奏、意象、情感密度、留白）方面的具体问题，给出修改方向和范例
3. **结构评估**：三层递进（常层→偶层→稀层→终局）在当前实现中是否真正产生了"越来越深入"的情感爬坡效果？如果不是，问题在哪？
4. **角色间化学效应**：10位角色之间是否存在隐性的关系网？如果没有，是否应该建立？
5. **重写优先级**：10位角色中，哪位重写的ROI最高（人设潜力最大但当前文本最拉胯）？请给出前3位
6. **风格锚点**：给出每位角色的一句话"声音锚点"（voice anchor）——一个能定义ta说话风格的句子/意象/节奏描述
7. **范例重写**：为优先级最高的3位角色，各重写3-4条叙事文本（含常层/偶层/稀层），让开发者直接对比"改前 vs 改后"
