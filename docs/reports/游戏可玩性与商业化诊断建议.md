# 异世界图书馆 · 游戏可玩性与商业化诊断建议

> 文档日期：2026-05-15
> 审查范围：核心玩法循环、留存机制、商业化路径

---

## 一、核心诊断：半个闭环

### 设计逻辑链

```
专注抄书 → 获得代币+氛围 → 升级借阅区 → 吸引访客 → 访客事件+好感 → 解锁更多内容
```

### 玩家实际体验

```
专注抄书（1次/5分钟）→ 专注抄书（又1次）→ 专注抄书（还是1次）→ …… 
→ 专注抄书 → 访客来了？好像没来？
→ 我为什么要继续？
```

**问题不在内容不够，而在体验节奏断裂。**

你设计了 22 本书、4 个 NPC、30 个成就、5 个氛围阶段——但**一个首次打开的新用户，前 20 分钟只能体验到"选书→专注→结算"这 3 件事**，而且：
- 结算卡每 25 分钟才出现一次
- 访客系统访客不出现（`借阅区 Lv0 = 容量0`，新用户根本无法体验访客！）
- 成就前 20 分钟几乎解锁不了任何东西
- 书架空空荡荡，没有仪式感

**这不是"内容不够"，是"钩子太深"。**

## 二、第一优先级：修复访客系统的"新手玻璃天花板"

这是整个留存设计的阿喀琉斯之踵。看这行代码：

```javascript
// visitors.js 第153-154行
const blvCfg = getBorrowLevelConfig();
if (blvCfg.cap === 0) return;  // ← Lv0 = 0人容量，直接return！
```

**新用户借阅区是 Lv0，容量为 0，访客系统完全不触发。**

这意味着新用户头 20 分钟的游戏体验是 **100% 纯孤独的单机番茄钟**，没有访客、没有事件、没有随机惊喜——这跟用普通计时器有什么区别？

### 建议方案

| 方案 | 描述 | 推荐度 |
|------|------|--------|
| **方案A（推荐）** | 借阅区 Lv0 时保留 1 人容量 | ⭐⭐⭐⭐⭐ |
| 方案B | 新手期间（累计<2次专注）保证至少 1 位访客在场 | ⭐⭐⭐⭐ |
| 方案C | 借阅区 Lv0 时用"路过的旅人"代替正式访客，作为新手引导的一环 | ⭐⭐⭐⭐⭐ |

**这一步完成后，新用户第一次专注回来，就能看到"有人在图书馆里了"——世界立刻有了生命。**

## 三、第二优先级：强化结算卡的"爽感密度"

现在每次专注（25分钟真实时间）只弹出一次结算卡，内容是：
> 分钟数 / 誊抄字数 / +N 智慧之光 / 引言

**25 分钟体验，3 秒的成就确认，这不够。**

### 分层设计结算卡的"爽感层级"

| 完成事件 | 弹什么 | 效果 |
|---------|--------|------|
| 普通专注完成 | 基础结算卡 | 知道收获了多少 |
| 连续第 2/3 次专注 | + 连击提示，"🔥 高效！" | 激励连续 |
| 章节解锁 | **章节解锁动画**（哪怕是个小卡片） | 里程碑感 |
| 书籍完成 | **书籍完成动画**（已有 ✅） | 高光时刻 |
| 访客在场完成 | 访客抬头的微小动画 | 世界有反应 |
| 里程碑触发 | 里程碑弹窗 | 长期目标感 |
| 成就触发 | 成就 toast（已有 ✅，但时机可更提前） | 正向反馈 |

## 四、第三优先级：氛围系统的"即时可见性"

你设计了 5 个氛围阶段（废墟→星辰），但氛围值增长极其缓慢（专注 1 分钟 = +1 氛围），新用户要专注 **160 分钟** 才能从"废墟"升到"陈旧"阶段。

**问题：氛围阶段变化太慢，新用户根本感受不到"图书馆在变好"。**

### 建议

1. **氛围值小数显示**：不需要等整数阶段变化，氛围值本身实时增长，顶部导航栏氛围条随时在走
2. **氛围阈值降低**：初期氛围增长更快（+3~5/次专注），让玩家 **5-10 次专注内** 至少体验一次阶段变化
3. **氛围变化有视觉反馈**：每次专注结算时，如果氛围有增长，可以有一个微小但明显的"光芒扩散"动画

## 五、第四优先级：解决"自己觉得好玩，但用户可能不来"的核心恐惧

**创作者的盲点：你太了解这个世界的设定，以至于会在脑子里脑补出大量"虽然 UI 没显示，但故事里是这样……"的体验。**

### 隔离测试法

找一个完全不了解你这个项目的朋友（或者自己开一个匿名浏览器窗口），让他/她从"打开页面"开始用，**不许解释任何规则**，只观察：

1. 第 1 分钟在干什么？有没有卡住？
2. 第 5 分钟有没有觉得"这个东西有意思"？
3. 第 10 分钟有没有想关掉？

这个测试的结果会比你问任何人都真实。

### B/C 问题的本质：目标感缺失

当前新用户看到的是：
- 书架有几本书 ✓
- 有一个计时器 ✓
- 氛围值显示 0/500 ✗（不知道这个数字代表什么）

**建议在新手引导结束页直接给出 3 个明确的当前目标：**

```
🎯 继续誊抄，《小王子》第 5 章即将解锁
🎯 再专注 3 次，第一位访客就会到来
🎯 收集 300 智慧之光，解锁第一个书架格子
```

## 六、商业化模式讨论

你的核心资产：**番茄钟 + 书籍 + 叙事 + 养成**

### 路径 A：Freemium + 道具付费（最主流）

- 基础功能免费（2 本初始书 + 基础番茄钟）
- 付费解锁更多书籍（每本 ¥3-6，或者月卡制 ¥15-30）
- 付费装饰/皮肤（图书馆外观、羽毛笔样式）
- 访客故事线付费解锁（像章节小说一样）

| 优点 | 缺点 |
|------|------|
| 收入模型清晰，微信/支付宝内购即可 | 用户付费意愿需要内容支撑，早期需要大量书籍内容 |

### 路径 B：订阅制 + 社区（更可持续）

- 月费 ¥9.9 / 年费 ¥99，解锁全部书籍
- 加入读者社区，可以看到全服专注时长排行（不竞争，只展示）
- 每月共读挑战（全员一起专注解锁奖励）
- 异步社交：看到"你的朋友 @xx 今天专注了 45 分钟，正在读《红楼梦》"

| 优点 | 缺点 |
|------|------|
| 长期留存好，用户黏性高 | 需要早期有足够好的内容吸引订阅 |

### 路径 C：企业/教育版（意想不到的蓝海）

- 为学校/图书馆/企业定制，专注时段打卡
- 管理员可看到团队专注数据（匿名聚合）
- 按人数收费（B2B 模型）

**这是最值得考虑的方向，因为：**
1. 产品天然适配"专注+阅读"场景
2. 政府/学校/企业有付费意愿和预算
3. 不需要海量用户，靠少数大客户就能养活项目

## 七、工作优先级建议

### Phase 1（发布前必须做）

1. 修复借阅区 Lv0 的访客玻璃天花板
2. 新手引导增加 3 个明确当前目标
3. 氛围值实时可见（不只是整数阶段）
4. 结算卡增加章节解锁小弹窗（哪怕是简单文字）

### Phase 2（发布后 1 个月内迭代）

5. 完整访客循环体验一遍
6. 书架书籍可视化（哪怕只是 emoji 卡片）
7. 访客好感度系统接入（目前访客有 favorability 字段但 UI 看不到）
8. 首次书籍完成时的仪式感动画

### Phase 3（商业化准备）

9. 付费书籍解锁系统
10. 企业/教育版数据面板

## 八、总结

> 你现在的代码质量、系统架构、内容体量都已经超过大多数独立游戏项目。唯一缺的是——让一个新用户在打开页面 5 分钟内说"哎，有点意思"。
>
> **修复访客的玻璃天花板，是投入产出比最高的一步。**
