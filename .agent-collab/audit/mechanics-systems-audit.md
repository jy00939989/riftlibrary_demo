# 核心玩法循环审计

> 日期: 2026-05-18 | 审计者: Claude Code + gsp-mechanics-systems-audit
>
> 评估项目: 异世界图书馆 (library_demo)

---

## 主循环结构

```
专注誊写 → 赚币+氛围 → 买书/升级 → 解锁更多书 → 吸引访客 → 成就触发 → 继续专注
```

## 优势

- **主 Verb 清晰** — 专注誊写定义明确，番茄钟/倒计时/正计时三种模式
- **系统间有联动** — 专注收益流向商店经济，氛围影响背景和 BGM，访客概率受氛围加成
- **数值骨架完整** — 币、氛围、速率、书架容量、升级价格曲线都有公式支撑
- **首次体验丰富** — 墨墨魔法加速、PV 开场、5步引导、首书完成仪式感、典藏证书
- **成就系统覆盖面广** — 31 个成就跨 6 个类别，检测点接入合理

## 核心问题

### 1. 循环过度依赖单一动作

专注是唯一有意义的事。升级缮写室只把速度从 1.0× 提到 1.3×，换本书抄只是换个书名。专注的体验在氛围 0 和氛围 500 时完全一样。没有任何系统反过来改变"专注"这件事本身。

### 2. 经济系统没有选择压力

```
每分钟固定 0.8 币 + 100 字
所有消费都是纯线性升级
买书 500-800，借阅区 500×1.5ⁿ，缮写室 400×1.45ⁿ
```

没有"先升级哪个划算"的策略空间——只是等币够了点一下。

### 3. 没有失败回路 — 零风险、零张力

- 放弃专注还能拿 50% 收益
- 没有任何资源会损失
- 每日任务不做也没惩罚
- 植物 72 小时不浇水才凋谢

这导致游戏变成纯"打卡"——缺乏让玩家紧张或需要决策的时刻。

### 4. 奖励回路前期满载、后期空洞

| 阶段 | 体验 |
|------|------|
| 前 5 次专注 | 墨墨出场 → 首书完成 → 首章解锁 → 首次访客 → 氛围升级 → 引导卡片 → 典藏证书 |
| 第 50 次专注 | 计时器滴答 → 结算卡片 → 数字 +N |

### 5. 多个系统是空壳

| 系统 | 状态 |
|------|------|
| 标志牌 | 买了什么都不发生（"buff效果为技术债"） |
| 位面系统 | 占位数据，完整实现在待办 |
| 古籍修复 | `damaged/repairWords` 字段存在但未接入循环 |
| 访客好感度 | 完全未实现 |
| 里程碑奖励 | 代码有 `// TODO: 后续连接到data/book_pool.js` |

### 6. 24 本书是 24 个相同玩具

唯一的区别是总字数。章节只是门槛数字，不是玩法节点。86 万字的《西游记》和 5 千字的《道德经》在抄写体验上没有差异。

## 打分

| 维度 | 评分 | 说明 |
|------|------|------|
| 主 Verb 清晰度 | ⭐⭐⭐⭐ | 清晰，但缺乏深度 |
| 奖励回路完整性 | ⭐⭐⭐ | 前期饱满，后期干瘪 |
| 失败回路 | ⭐ | 不存在 |
| 经济策略深度 | ⭐⭐ | 线性升级，无选择压力 |
| 系统间耦合度 | ⭐⭐⭐ | 联动存在，但多是单向 |
| 功能完成度 | ⭐⭐⭐ | 核心可用，6+ 系统是壳 |

## 总评

特征是"堆了足够多系统让前 2 小时体验丰富"，但循环缺乏深度——一旦玩家发现所有路都通向同一个终点（赚币→升级→赚更多币），动力就会断崖式下跌。建议优先：给经济系统加入策略选择（先升级什么有不同后果）、为专注体验注入变量（不同书籍有不同抄写效果）、闭合至少 2 个空壳系统。
